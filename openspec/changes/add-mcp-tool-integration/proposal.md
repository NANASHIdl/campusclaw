# Change: add-mcp-tool-integration

## Why

第 5 课把「检索」接进了回答，但回答只能用本班材料里的文字。教学场景里还有一类需求材料给不了：**让学生自己算一步**——查公式、做单位换算。这类能力不是「一段可检索的文本」，而是一个**动作**：给参数、返回结果。

把这类能力硬编码进主应用，每加一个就要改一次主应用、重新发一次版；而工具源往往由别人维护（学科老师、第三方服务），改动节奏和主应用完全不同。MCP 把这两件事拆开：**工具服务器只实现一次协议，宿主按同一套发现结果生成工具声明并负责执行**。于是「接一个新工具」从改代码变成改配置。

工具一旦能被真实调用，风险就从「文字」升级为「动作」：模型会读工具说明、会按说明提出调用，而说明与返回都是不可信文本；调用又带着宿主的令牌。所以本课除了「接进来」，还要补上三件事：**最小权限的候选集、有上限的调用循环、可追溯的调用记录**。

## What Changes

### 一、自建 MCP 工具服务（新增 `mcp-server/`）

- 与主应用同一工程、同一 `docker-compose.yml`，服务名 `mcp-demo`，只在容器网络内可达（不映射宿主机端口）。
- 实现协议的三个方法：`initialize`（能力协商）、`tools/list`（工具发现）、`tools/call`（执行工具）；报文为 **JSON-RPC 2.0**，单入口 `POST /mcp`，另提供 `GET /health`。
- 令牌取自环境变量 `MCP_AUTH_TOKEN`；无令牌或令牌不符一律拒绝；非法报文返回可读的 JSON-RPC 错误（`-32700` 解析错误、`-32600` 请求非法、`-32601` 方法不存在、`-32602` 参数非法）。
- 暴露两个工具，每个都写全**名称、说明、输入结构**：
  - `formula_hint`：按主题给一条公式提示（只给提示，不给最终答案）；
  - `unit_convert`：单位换算（长度/质量/时间/温度），支持连续两步换算。
- 返回 `content` 数组（文本项）与 `isError` 标记；返回里不夹带指令式语句。

### 二、宿主侧：登记、连接、发现、断开

- 新增 8 个接口：`GET/POST /api/mcp/servers`、`PUT/DELETE /api/mcp/servers/{id}`、`POST /api/mcp/servers/{id}/connect`、`POST /api/mcp/servers/{id}/disconnect`、`GET /api/mcp/servers/{id}/tools`、`GET /api/mcp/tool-calls`。
- **令牌只存服务端**：`auth_token` 落库，任何响应只回 `has_auth` 布尔值；日志不记令牌；前端输入框为密码类型、提交即清空。
- 写操作仅教师（`403`）；按编号访问他班或不存在的服务器一律同构 `404`。
- 「连接」＝**握手 + 发现**两步，任一步失败就停在未连接并给出可读原因；两步都成功才用本次清单**整体替换**旧清单并标记已连接。连续连接两次，清单条数不翻倍。
- 「断开」＝清空清单并置为未连接；此后引用它上面工具的技能，调用一律记为「被拒」。
- 连接失败不阻断检索与流式对话主路径（工具是增益而非主路径）。

### 三、工具声明与调用编排

- 技能的「工具」项除内置 `knowledge_search` 外，支持引用 `工具名@服务器名`（如 `formula_hint@campus-tools`）；工具名小写字母开头、不含连字符，服务器名允许连字符。
- **保存前校验**四件事：格式、服务器是否登记、服务器是否已连接、工具是否在最近一次发现清单内。任一不满足即 `400` 并给出可读提示。
- **候选集与最小权限**：本次请求只带命中技能所引用的工具；技能没有引用则不带任何工具声明（模型看不到任何工具）。
- **决策归模型、执行归宿主**：工具声明随请求发给模型；模型提出调用后，宿主按同一份 `inputSchema` 校验参数，再带令牌发 `tools/call`。
- **结果清洗后回传**：命中指令式句式的整条丢弃并换成固定说明，过长截断；结果作为**工具消息**落在数据位（用户消息一侧），由模型组织最终回答。
- **循环有终止也有上限**：轮次上限与单次提问累计调用次数上限；超限后**优雅降级**——停止调用，让模型用已有信息作答，不报错中断。
- **调用先于正文**：SSE 的 `meta` 中带 `tool_calls`（`ref`/`status`/`text` 摘要），仅本次确有调用时出现；未连接或越权调用记为 `denied`，不静默成功。

### 四、调用记录

- 新增 `mcp_tool_calls`：一次调用一条，记录 `tool_ref`、`server_name`、`status`（`ok`/`denied`/`error`）、触发用户、会话与轮次、时间、结果摘要或失败原因。
- 只增不改；管理角色只能看本班记录，默认按时间倒序取最近 50 条。
- 服务器被改名或删除后，本次调用**无处归属、不写记录**——这是预期行为，不是缺陷（失败仍体现在本次应答的 `tool_calls` 里）。

### 五、接口文档与测试

- 8 个新接口补齐 swaggo 注解（`@Security`/`@Param`/`@Success`/`@Failure`/`@Router`），启动自检的路由集合随之扩大。
- `apitest/` 增加本课用例：登记、连接、列出工具、断开、非教师被拒，以及一条端到端（连接 → 绑定 `formula_hint@…` → 提问 → 记录出现一条成功）。
- 新增 `scripts/verify_mcp.py` 端到端验收。

## Capabilities

### New Capabilities

- `mcp-server`：JSON-RPC 2.0 单入口、三个方法、令牌校验、两个工具的声明与执行、健康检查。
- `mcp-tools`：宿主侧登记与令牌边界、连接与发现、断开、引用格式与保存前校验、候选集、调用循环与上限、结果清洗与回传、SSE 调用可见、调用记录。

### Modified Capabilities

- `agent-chat`：技能文件的「工具」项由「只接受 `knowledge_search`」扩展为「内置项 + `工具名@服务器名` 引用」，且保存前要校验引用可用；SSE 的 `meta` 增加 `tool_calls` 字段。

`api-docs` **不需要 delta**：既有规约已要求「注解声明的操作集合 MUST 与注册的路由集合完全相等」，
新增 8 条路由只要漏了注解，服务就起不来——这条约束本身就强制本课补齐文档。

## Impact

- **新增服务**：`mcp-server/`（Go，仅标准库，独立模块），compose 增加 `mcp-demo`，`api` 通过 `MCP_BASE_URL` 之外的「服务器登记地址」连它。
- **新增数据表**：`mcp_servers`、`mcp_tools`、`mcp_tool_calls`。
- **新增 Go 包**：`api/internal/mcp`（模型、仓储、JSON-RPC 客户端、处理函数）。
- **改动**：`internal/skill`（工具项解析与引用校验）、`internal/chat`（调用循环）、`internal/qa`（带工具的请求与 tool_calls 解析）、`cmd/server`（8 条路由 + 注解）、`internal/db`（建表）。
- **前端**：新增「工具服务」管理页（登记、连接、工具清单、调用记录），对话页在回答前显示本次用到的工具。
- **环境变量**：`MCP_AUTH_TOKEN`（两侧一致）、`MCP_TIMEOUT_SECONDS`、`MCP_MAX_ROUNDS`、`MCP_MAX_CALLS`。

## Non-goals（非目标）

本 change **明确不做**以下内容（避免范围膨胀）：

- **MCP 的 resources / prompts 能力**：只实现 `tools` 一项，`initialize` 的能力协商里只声明 tools。
- **stdio 与 SSE 传输**：只做 HTTP `POST /mcp` 单入口，不做 stdio、不做 Streamable HTTP 的事件流。
- **指标与追踪**：可观测性只做到日志层（每次调用一条记录），指标与链路追踪属第 8 课。
- **人工确认（human-in-the-loop）**：本课两个工具都是只读、无外部副作用的提示类工具；「写操作/外发类操作需人点头」留到出现此类工具时再做。
- **工具说明变更检测与重新确认**：不做说明指纹、变更告警与二次批准流程；界面保证能看到完整说明。
- **多服务器并发与工具结果缓存**：一次提问内按顺序执行，不并行、不缓存。
- **学生自助管理服务器**：登记、改、删、连接、断开都只对教师开放。
- **调用记录的分页、导出与跨班聚合**：只做本班最近 50 条。
- **输出侧外发意图扫描**：回答送达前的最后一道检查属第 8 课。
