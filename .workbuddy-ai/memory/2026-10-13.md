## 构建 CampusClaw 可运行项目（最轻量方案）
- 技术选型：**Flask + SQLite（标准库 sqlite3）+ Jinja2 + werkzeug.security**，运行时依赖仅 Flask（gunicorn 仅容器用）。
- 按 SDD 顺序落地：先写 `openspec/changes/add-auth-rbac-class-knowledge/` 四件套，再按 tasks 实现。
- 实现内容：登录/会话（role+class_id）、服务端班级隔离（列表过滤 + 按 ID 403）、教师上传→解析→materials+knowledge_entries 双表入库、学生上传 403、GET /health、8 张表（含六类核心域表）、种子数据（班级 A/B、teacher_a、student_a1、student_b1）。
- Docker：`Dockerfile`（python:3.12-slim + gunicorn）、`docker-compose.yml`（volume 持久化 data/ 与 uploads/、healthcheck）、`.env.example`。
- 验收：本地端到端 17 项断言全 PASS；`openspec validate --strict` 通过（exit 0）。
- 环境坑：
  1. **pip 走代理装不上包**（curl 可通、pip 不行）→ 本机用系统 Python 3.10.6（已带 Flask 3.1.3）验证；用户自建 venv 时若遇同样问题需检查代理。
  2. **openspec config.yaml 的 `rules` 必须是「artifact id → 字符串数组」的对象**（不是列表）；`schema: spec-driven` 必填；YAML 里含 `X: ` 的文本要加引号。
  3. werkzeug 3.x 默认密码哈希是 `scrypt:...`（非 pbkdf2）。
  4. 本机 Docker daemon 未运行，容器级实测未做。
